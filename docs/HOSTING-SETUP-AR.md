# إعدادات استضافة نظام فكرتك للمؤثرين

## التشغيل

يتطلب الإصدار Node.js 24 أو أحدث. ملف الدخول هو `server.mjs` في جذر الحزمة. لا توجد اعتماديات تشغيل خارجية ولا حاجة إلى `npm install`. شغّل في مجلد الحزمة:

```sh
npm start
```

يشغّل الأمر `start-production.sh` ثم `server.mjs` في الواجهة الأمامية. على Windows استخدم `start-production.cmd`. لا يتطلب التطبيق systemd أو Nginx كي يبدأ؛ لكن الاستضافة العامة تحتاج وسيلة مناسبة لإبقاء العملية عاملة، وHTTPS/وكيلًا عكسيًا وفق متطلبات مزودها.

## متغيرات البيئة

| المتغير | المعنى | مثال غير سري | إلزامي؟ |
|---|---|---|---|
| `NODE_ENV` | وضع التشغيل؛ استخدم `production` لتفعيل ضوابط الإنتاج | `production` | نعم للإنتاج |
| `PORT` | منفذ HTTP الذي يستمع عليه الخادم | `8765` | لا؛ الافتراضي `8765` |
| `FIKRATAK_HOST` | عنوان الربط المحلي | `127.0.0.1` | لا؛ الافتراضي `127.0.0.1` |
| `FIKRATAK_DATA_DIR` | مجلد قاعدة SQLite والبيانات؛ يجب أن يكون مسارًا مطلقًا خارج مجلد التطبيق | `/var/lib/fikratak/data` | نعم في الإنتاج |
| `FIKRATAK_BACKUP_DIR` | مجلد النسخ الاحتياطية؛ يجب أن يكون مسارًا مطلقًا خارج مجلد التطبيق | `/var/backups/fikratak` | نعم في الإنتاج |
| `FIKRATAK_ALLOWED_ORIGINS` | أصول HTTPS المسموح بها، مفصولة بفواصل، ويجب أن تطابق عنوان المتصفح تمامًا | `https://crm.example.com` | نعم في الإنتاج |
| `FIKRATAK_SETUP_TOKEN` | رمز مؤقت لصفحة إنشاء أول مدير؛ عند ضبطه في الإنتاج يجب ألا يقل عن 32 بايتًا | يُحفظ في مخزن أسرار الاستضافة | لا للتشغيل؛ نعم للإعداد الأول عبر الصفحة |
| `FIKRATAK_IMPORT_ENABLED` | يفتح الاستيراد عند القيمة `1`؛ الافتراضي مغلق | `0` | لا |
| `FIKRATAK_TRUSTED_PROXIES` | عناوين IP للوكيل المباشر الموثوق، مفصولة بفواصل | `127.0.0.1` | لا |
| `FIKRATAK_LOGIN_MAX_ATTEMPTS` | عدد محاولات الدخول قبل القفل | `6` | لا؛ الافتراضي `6` |
| `FIKRATAK_LOGIN_LOCKOUT_MINUTES` | مدة قفل الدخول بالدقائق | `10` | لا؛ الافتراضي `10` |
| `FIKRATAK_LOGIN_URL` | عنوان HTTPS المستخدم بأداة إنشاء/إعادة تعيين مدير الإنتاج | `https://crm.example.com` | لا؛ للأداة الإدارية فقط |
| `FIKRATAK_AGE_RECIPIENT` | مفتاح age العام لتشفير نسخة خارجية | قيمة عامة من إعدادات النسخ | لا؛ عند استخدام النسخ الخارجي |
| `FIKRATAK_OFFSITE_TARGET` | وجهة SSH/rsync للنسخ المشفر الخارجي | `backup-user@backup.example:/srv/backups/fikratak` | لا؛ عند استخدام النسخ الخارجي |
| `FIKRATAK_AGE_IDENTITY_FILE` | مسار هوية age الخاصة لاستعادة نسخة خارجية | `/etc/fikratak/backup-identity` | لا؛ للاستعادة فقط |
| `FIKRATAK_RESTORE_DATA_DIR` | مجلد بيانات بديل مؤقت لأداة الاستعادة | `/var/tmp/fikratak-restore/data` | لا |
| `FIKRATAK_RESTORE_BACKUP_DIR` | مجلد نسخ بديل مؤقت لأداة الاستعادة | `/var/tmp/fikratak-restore/backups` | لا |
| `FIKRATAK_VERIFY_REMOTE_TARGET` | وجهة اختبار منفصلة للتحقق من النسخ الخارجي | `backup-user@backup.example:/srv/backups/verify` | لا؛ لاختبار التشغيل فقط |

لإنشاء رمز إعداد عشوائي، ولّده في بيئة موثوقة واحفظه في مخزن أسرار الاستضافة؛ لا تضعه في ملفات المشروع أو سجل الأوامر. مثال لتوليد hex بطول 32 بايتًا:

```sh
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

لا تضبط `FIKRATAK_TRUSTED_PROXIES` إلا بعناوين الوكلاء التي أكدها مزود الاستضافة. لا يثق التطبيق تلقائيًا بترويسات `X-Forwarded-For` من اتصالات غير موثوقة. متغيرا `FIKRATAK_ENABLE_ALIAS_NORMALIZATION` و`FIKRATAK_AXE` خاصان بالتطوير/الفحص، ولا يفعّلان سلوكًا إنتاجيًا.

## إنشاء أول مدير وتفعيل الاستيراد

1. اضبط `FIKRATAK_DATA_DIR` و`FIKRATAK_BACKUP_DIR` و`FIKRATAK_ALLOWED_ORIGINS`، ثم شغّل التطبيق مع `FIKRATAK_SETUP_TOKEN` عشوائي بطول 32 بايتًا على الأقل.
2. استخدم صفحة إعداد أول مدير خلال 30 دقيقة من بدء الخادم. الرمز الخاطئ مرفوض، وبعد إنشاء أول حساب لا تسمح الصفحة بإنشاء مدير آخر.
3. بعد نجاح الإنشاء، احذف `FIKRATAK_SETUP_TOKEN` من إعدادات الاستضافة وأعد تشغيل الخدمة.
4. الاستيراد مغلق افتراضيًا. عند الحاجة، فعّل `FIKRATAK_IMPORT_ENABLED=1` مؤقتًا ثم أعد تشغيل التطبيق، ونفّذ الاستيراد بحساب `admin` أو `editor`، وأعده إلى `0` بعد الانتهاء. يظل `viewer` للقراءة فقط.

## ما يبقى وما يفقد عند إعادة التشغيل

تبقى قاعدة البيانات `fikratak.sqlite` والنسخ الموجودة في المجلدات المضبوطة ما دامت تلك المجلدات محفوظة من مزود الاستضافة. تنتهي الجلسات الخادمية، وقفل محاولات الدخول، ومعاينات الاستيراد المؤقتة عند إعادة تشغيل العملية؛ يلزم تسجيل الدخول مجددًا. المؤقتات داخل العملية تتوقف أثناء الإيقاف وتُنشأ من جديد عند التشغيل. لا يحمي مسار خارج التطبيق البيانات إذا كان مزود الاستضافة يحذفه عند إعادة النشر أو إيقاف الخدمة.

## ما لم يمكن التحقق منه محليًا

لم يُختبر مزود استضافة بعينه؛ لذلك يلزم التحقق من: المنفذ وعنوان الربط اللذين يتطلبهما، واستمرار مجلدي البيانات والنسخ بعد إعادة رفع التطبيق، وعنوان IP الذي يصل إلى الخادم خلف الوكيل، وإمكانية تشغيل `cron` أو المجدول الذي يوفره. لا تفترض أن هذه الخصائص متاحة أو دائمة دون تأكيد من المزود. لم تُختبر إعدادات HTTPS أو الوكيل أو الشبكة لدى مزود فعلي.
